API

Every itinerary the web UI creates is reachable over the REST API. The contract is published as OpenAPI 3.1 at /api/openapi.yaml — point your generator of choice at it.

Authenticate

Create a token at /settings, then send it as a bearer token.

curl -H "Authorization: Bearer $TRAVEL_NEXT_TOKEN" \
  {{ .BaseURL }}/api/v1/me

Create an itinerary

Returns 202 Accepted straight away; poll the itinerary until status leaves generating.

curl -X POST {{ .BaseURL }}/api/v1/itineraries \
  -H "Authorization: Bearer $TRAVEL_NEXT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "destination": "Kyoto, Japan",
    "start_date": "2026-04-02",
    "end_date": "2026-04-09",
    "travellers": 2,
    "pace": "balanced",
    "budget": "mid-range",
    "currency": "AUD",
    "interests": ["food and markets", "history and museums"],
    "audience": "family at home"
  }'

Endpoints

GET /api/v1/meThe authenticated user
GET /api/v1/form-optionsVocabulary from the prompt-context ConfigMap
GET /api/v1/itinerariesList your itineraries
POST /api/v1/itinerariesCreate one and start generation
GET /api/v1/itineraries/{id}Fetch one, including the generated document
PATCH /api/v1/itineraries/{id}Publish or unpublish
DELETE /api/v1/itineraries/{id}Delete
GET /api/v1/tokensList tokens
POST /api/v1/tokensCreate a token
